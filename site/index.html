What developers actually ask.

One query each. No embeddings, no training set, no vector column — and the second run costs nothing.

Route every ticket to the right team

SELECT jev_choice(tickets, 'which team should handle this?',
                  ARRAY['billing','technical','security','sales']) AS team,
       count(*)
FROM tickets GROUP BY 1 ORDER BY 2 DESC;

Per-team counts from a sentence, replacing the keyword rules nobody wants to maintain.

Rank accounts by churn risk

SELECT subject, jev_prob(tickets, 'the customer is about to churn') AS p
FROM tickets ORDER BY p DESC LIMIT 20;

A calibrated 0..1 per row, so you choose the threshold instead of guessing it.

Score a catalogue on a rubric

SELECT name, jev_score(products, 'how luxurious is this?',
                       ARRAY['budget','mid-range','premium','luxury']) AS tier
FROM products ORDER BY tier DESC;

Ordered levels with no labelled data, comparable across every row.

Filter the way you would say it

SELECT * FROM people
WHERE jev(people, 'the name is European') AND age > 40;

It is a boolean, so it composes with every join, index and predicate you already have.

Judge once. Store the answer. Read it back.

Hosted SQLite has no user-defined functions and cannot call the network from SQL, so the model call moves to JavaScript and the answers move into a table.

Or tag it into a column

One call writes jev_* 0/1 values and an index. After that the predicate is plain SQL.

0.07 ms at 20,000 rows
-- your query, rewritten: no extension, no user-defined function, no network from SQL
SELECT * FROM people
WHERE (COALESCE((SELECT j.prob FROM jev_judgments j
                 WHERE j.scope = 'people'
                   AND j.row_ref = CAST("people"._rowid_ AS TEXT)
                   AND j.judgment_key = 'noul…the name is European…'), -1.0)
       >= COALESCE(0.5, 0.5));

Start — 2 minutes

  • Full scan, on purpose. Every scanned row goes to the model once.
  • Row contents leave your machine. They go to TypeSafe.
  • jev() needs a row id table. Views and CTEs use the JS row API.
  • D1 allows 1000 queries per Worker invocation. 5,000 rows is about 37 — warm big tables on a schedule.
  • Changing model re-judges. jev-latest and jev-1.13.0 never share answers; a change inside the alias needs a pinned version or a cleared table.
1. git clone https://github.com/sashimikun/sql-jev && cd sql-jev && bun install
2. sqlite3 demo.db < sql/sql-jev.sql
3. export TYPESAFE_API_KEY=...   # console.typesafe.ai
// 4. ask.ts
import { Database } from 'bun:sqlite';
import { createJev } from 'sql-jev';

const db = new Database('demo.db');
const jev = await createJev({ db, apiKey: process.env.TYPESAFE_API_KEY });
const { rows } = await jev.query(
  `SELECT name FROM people WHERE jev(people, 'the name is European')`,
);

Deploy — one command

Schema, secrets and a Worker where the platform needs one. --dry-run prints the commands without running them.

bunx sql-jev deploy turso --db my-db            # Turso, ~3 min
bunx sql-jev deploy d1 --db my-db --worker      # Cloudflare D1, ~5 min
sqlite3 my.db < sql/sql-jev.sql                # plain SQLite, 5 sec
